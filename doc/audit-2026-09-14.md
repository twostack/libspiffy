## 1. Summary

Critical and High come from the findings index, Medium and Low from sections 7 and 8. **By area**

| Actor layer | `A-` | 2 | 8 | 10 | 6 |

(KM-3 and H1, KM-6 and H2 describe the same defects from two angles and are
counted once, under the core.)

**The picture in three sentences.** The cryptographic primitives, the event
serialisation contracts and the SQL layer are sound. The defects cluster in
the seams: coordinators that bypass the aggregate, three storage backends
that disagree on semantics, an SPV layer whose trust boundaries are not
closed, and actor handlers that block their own mailbox. The one open
Critical (S-01) is confined to the Postgres payment-channel read model,
which cannot have worked since it was written.

**Mutation verification of the fixes (added after release 2.0.0).** The
2.0.0 release shipped regression tests for only four of the 27 fixed
findings (A-C1, SPV-01, S-02, S-03), and none of those had been shown to
fail on the pre-fix code. Every finding marked Fixed, Mitigated or Partial
now has a `Test` row naming a test that was run twice: once with the fix
hunk reverted (it must fail with the reported symptom, quoted in the row)
and once with the fix restored (it must pass). A-H2's payment-coordinator
site is covered by a static guard rather than a behavioural test. Doing
this surfaced five further defects, listed in
[section 11](#11-defects-found-while-verifying-the-fixes); all five are
fixed and covered the same way. Epic libspiffy-hwz tracks the work.

## 3. Dependency upgrade notes

`dactor ^1.3.0`, `eventador ^3.0.0`, `duraq ^3.0.0`, `duraq_isar ^2.0.0`.
All four are on pub.dev; the eventador path override is gone.

| # | Change | Who is affected | What to do |
|---|---|---|---|
| 1 | `IsarStorage` moved to `duraq_isar` | Hosts constructing DuraQ queues on the shared Isar | Import `package:duraq_isar/duraq_isar.dart` |
| 2 | `BitcoinWalletAggregate.preStart` is `Future<void>`; recovery runs inside it and dactor awaits it, so `spawn()` returns a recovered aggregate | Code calling `preStart()` directly; tests | `await` it. The 200 ms settle sleeps and the `RecoveryStatusQuery` poll were removed from `WalletManagerActor` and `InvoiceCoordinatorActor` |
| 3 | A host-supplied Isar must be opened with `LibSpiffySchemas.allSchemas` | Hosts sharing an Isar instance | `initialize` now throws an `ArgumentError` naming the missing collections. Under eventador 3.0 a projection whose checkpoint collection is missing stops in `ProjectionStatus.error` instead of replaying from 0, so the old partial-schema setup would leave read models silently frozen |
| 4 | `ask()` no longer retries | Nobody: libspiffy never depended on retries | The old default re-sent commands to slow aggregates up to four times |
| 5 | duraq 2.0/3.0 migrate the broadcast-retry queue database in place on first open | Deployments that might roll back | Back the file up; duraq 1.x cannot reopen it. `ARCActor` uses `processNext` (at-least-once), so the `dequeue()` change does not apply |
| 6 | eventador 3.0 tags `DateTime` in CBOR | Nobody | Every libspiffy `fromMap` already accepts `String` and `DateTime` |
| 7 | `PostgresEventStore` brought to the 3.0 `EventStore` contract | Postgres deployments | `Event.typeName` / `State.typeName` for type columns, `persistableMetadata` for the metadata column, replay-then-live subscription (see S-00) |

## 5. Critical findings

### SPV-01 · security · Fixed
**Unproven payment accepted without its inputs being covered by proven ancestors**

| | |
|---|---|
| File | `lib/src/actors/spv_actor.dart:284-319, 410-460` |
| Failure | For a subject transaction with no BUMP, the actor validated every transaction in the BEEF that *had* a proof but never checked that the subject's inputs chained back to any of them, and `_validateTransactionSpendsCorrectly` skipped inputs whose funding transaction was absent. A BEEF holding one real mined transaction plus a self-signed payment spending non-existent outpoints validated, `_extractSpendableUTXOs` credited the outputs, and the invoice was marked paid. |
| Fix | Every input of an unproven transaction must resolve, recursively through the BEEF, to a transaction with a validated proof (BRC-62). An unproven transaction whose funding transaction is missing now fails script validation. Proven subjects are unaffected. |
| Test | `test/integration/full_spv_validation_test.dart` "rejects an unproven payment whose inputs are not covered by the BEEF". Mutation-verified: with the `spv_actor.dart` hunk reverted it fails (`Expected: false, Actual: true`); the other three tests in the file still pass, so it is the sole discriminator. |

### A-C1 · correctness · Fixed
**HeaderSyncActor polled its own mailbox for a header it could not receive while polling**

| | |
|---|---|
| File | `lib/src/actors/header_sync_actor.dart:493-590`; `spv_actor.dart:202-208`; `integration/spiffynode_bridge.dart:133-140` |
| Failure | `_handleSpecificHeaderRequest` sent `getHeaders` then slept and polled storage inside `onMessage`. Headers arrive as `BlockHeadersReceivedMessage` on the same actor and are stored only by `_handleBlockHeadersReceived`, which could not run while the handler held the mailbox. Every opportunistic fetch timed out after 10 s, header sync was blocked for that period, and the asking `SPVActor` waited up to 15 s per validation. |
| Fix | Requests are parked in a per-height map and answered from `_handleBlockHeadersReceived`; a timer answers the timeout. `postStop` cancels the timers. |
| Test | `test/actors/header_sync_actor_test.dart` group "Specific header requests". Mutation-verified: with the hunk reverted both tests fail ("Timeout waiting for header at height 5 after 5s"; follow-up ask took 504 ms instead of returning immediately). |

### A-C2 · correctness · Fixed
**Client-side channel open stalled: `BuildFundingTransactionCommand` was sent to an actor that dropped it**

| | |
|---|---|
| File | `lib/src/actors/channel_p2p_adapter.dart:178`; `payment_channel_manager_actor.dart:102-143` |
| Failure | On `channel_accept` the adapter told the channel manager a wallet command that only `BitcoinWalletAggregate` handles. The manager's `default:` discarded it, no `FundingTransactionBuiltResponse` was ever produced, and the refund/open sequence never started. |

| Test | `test/actors/channel_p2p_adapter_test.dart` "channel_accept routes BuildFundingTransactionCommand to the wallet manager". Mutation-verified: old routing gives `Expected: length 1, Actual: []` on the wallet-manager probe. |

### C1 · correctness · Fixed
**Deferred-spend UTXOs could never be marked spent; they returned to `available` after the reservation expired**

| | |
|---|---|
| File | `lib/src/core/bitcoin_wallet_aggregate.dart:879`; `payment_coordinator_actor.dart:1099, 262`; `arc_actor.dart:534` |
| Failure | The coordinator reserves the inputs (2-minute expiry) and records the transaction with `deferSpend: true`, expecting ARC to send `SpendUTXOCommand` at SEEN_ON_NETWORK. `_handleSpendUTXO` rejected any UTXO not in `available`, so the spend never applied; the expiry cleanup then returned the on-chain-spent coin to `available` (balance overstated, coin re-selectable, double-spend attempt). |

### S-01 · correctness · Fixed (post-2.0.0)
**Postgres channel read model cannot work**

| | |
|---|---|
| File | `lib/src/storage/postgres/postgres_wallet_storage.dart:1510, 1595, 1531-1541`; `projections/channel_projection.dart:142-166, 202, 224` |
| Failure | `ChannelProjection` passes Isar `PaymentChannelEntity` objects; Postgres casts them to `PaymentChannel` (`TypeError` on every channel event) and returns `PaymentChannel` where the projection casts to the entity. Even with the casts fixed, the `ON CONFLICT` clause never updates the server-side and funding fields, and `latestPaymentTxId`, `settlementTxId`, `errorMessage` have no columns. |

### S-02 · correctness · Fixed
**Postgres dropped `pluginMetadata`: token UTXOs were counted in the balance and selectable as payment inputs**

| | |
|---|---|

### H4 · correctness · Fixed (post-2.0.0)
**Key material stored after the success reply; a failed secure-storage write leaves an unrepairable keyless wallet**

| | |
|---|---|
| File | `bitcoin_wallet_aggregate.dart:119-163, 169-200, 74-82` |

| Test | `test/core/bitcoin_wallet_aggregate_key_material_test.dart` (mnemonic, WIF, xpriv; write-order log). Mutation-verified: old code journaled the event despite the storage failure. |

## 9. What was checked and found sound

|---|---|
| Cryptographic primitives | AES-256-GCM with CSPRNG nonces and verified tags; HKDF-bound row contexts; RFC 6979 low-S ECDSA via dartsv; `Random.secure()` everywhere; `SIGHASH_ALL\|FORKID` at every signing site |

| Untrusted input | BEEF/BUMP parsing terminates and bounds allocation; CDN chunk hashes verified before parsing and cached chunks re-verified; WhatsOnChain retries rate-limited; node-RPC credentials only in the Authorization header |
