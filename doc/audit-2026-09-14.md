# libspiffy code audit — 14 September 2026

Scope: `lib/` of libspiffy 1.1.0 (50,600 lines) as it stood before the
upgrade to dactor 1.3.0, eventador 3.0.0 and duraq 3.0.0 / duraq_isar 2.0.0,
reviewed for correctness, security, architectural soundness and performance.
This follows the same process used for the three dependencies (see
`../dactor/doc/audit-2026-09-14.md`, `../eventador/doc/audit-2026-09-14.md`
and `../duraq/docs/audit`). Findings marked **Fixed** were remediated in the
2.0.0 change set that accompanies this audit; **Mitigated** means the
failure is now loud instead of silent; everything else is **Open** and
tracked in beads under the label `audit-2026-09` (the bead title starts with
the finding id).

Every finding below was verified by reading the code path cited. Line
numbers refer to the pre-audit tree (commit `a68d4a7`).

## Verification

- `dart analyze` reports no errors in `lib/`, `test/` and `example/` (the
  example previously did not compile: it used classes the package does not
  export).
- The test suite was run three ways: on the upgraded tree, on an exact
  pre-upgrade baseline worktree (libspiffy `a68d4a7` with dactor 1.2.0,
  eventador 2.2.0, duraq 1.0.0), and per file where results differed. Every
  failure that remains on the upgraded tree also fails on the baseline; the
  list is in bead T-1. Counts on the final tree (network-dependent suites
  excluded): unit and local integration suites 1,300+ passing, 23 failing
  (all pre-existing, none caused by the upgrade or the fixes); Postgres
  suite 21/21 passing against a local PostgreSQL 16.
- Regression tests were added for the header-fetch deadlock (A-C1), the
  BEEF ancestor-coverage hole (SPV-01), the Postgres header nonce width
  (S-03) and plugin-metadata persistence (S-02).

## Dependency upgrade notes

`dactor ^1.3.0`, `eventador ^3.0.0`, `duraq ^3.0.0`, `duraq_isar ^2.0.0`.
All four are on pub.dev; the eventador path override is gone. Breaking for
libspiffy and for hosts:

1. **`IsarStorage` moved to `duraq_isar`.** Hosts that construct DuraQ
   queues on the shared Isar instance need `package:duraq_isar/duraq_isar.dart`.
2. **`BitcoinWalletAggregate.preStart` is `Future<void>`.** Recovery now
   runs inside `preStart` and dactor awaits it, so `spawn()` returns a
   recovered aggregate. Code that called `preStart()` directly must await it.
   The 200 ms "wait for recovery" sleeps and the `RecoveryStatusQuery` poll
   in `WalletManagerActor` / `InvoiceCoordinatorActor` were removed.
3. **A host-supplied Isar instance must be opened with
   `LibSpiffySchemas.allSchemas`.** eventador 3.0 puts a projection whose
   checkpoint collection is missing into `ProjectionStatus.error` instead of
   silently replaying from 0, and duraq's queue silently disabled itself when
   its collections were missing. `LibSpiffyActorSystem.initialize` now throws
   an `ArgumentError` naming the missing collections. Nine test files and the
   developer guide listed collections by hand and were updated.
4. **`ask()` no longer retries.** libspiffy never depended on retries; the
   old default re-sent commands to slow aggregates up to four times.
5. **duraq 2.0/3.0 migrate the broadcast-retry queue database in place** on
   first open; it cannot be reopened by duraq 1.x. `ARCActor` already used
   `processNext` (at-least-once), so the `dequeue()` semantic change does not
   affect it.
6. **eventador 3.0 tags `DateTime` in CBOR.** Every libspiffy event already
   accepts both `String` and `DateTime` in `fromMap`, so journals written by
   1.x decode unchanged.
7. `PostgresEventStore` was brought up to the 3.0 `EventStore` contract:
   `Event.typeName` / `State.typeName` for the type columns,
   `persistableMetadata` for the metadata column, and the same
   replay-then-live subscription as eventador's `IsarEventStore` (see S-00).

## Findings

Ids: `KM` key management and cryptography, `C`/`H`/`M`/`L` event-sourced
core, `A` actor layer, `S` storage, `SPV` SPV/network/transaction building.

### Critical

**SPV-01 · Critical · security · Fixed — An unproven payment was accepted
without its inputs being covered by proven ancestors.**
`spv_actor.dart:284-319, 410-460`. For a subject transaction with no BUMP
the actor validated every transaction in the BEEF that had a proof, but never
checked that the subject's inputs chained back to any of them, and
`_validateTransactionSpendsCorrectly` skipped inputs whose funding
transaction was absent. A BEEF holding one real mined transaction plus a
self-signed payment spending non-existent outpoints validated and the
invoice was marked paid. Now every input of an unproven transaction must
resolve, recursively through the BEEF, to a transaction with a validated
proof (BRC-62), and an unproven transaction with a missing funding
transaction fails script validation. Regression test in
`test/integration/full_spv_validation_test.dart`.

**A-C1 · Critical · correctness · Fixed — HeaderSyncActor polled its own
mailbox for a header it could not receive while polling.**
`header_sync_actor.dart:493-590`. `_handleSpecificHeaderRequest` sent
`getHeaders` and then slept/polled storage inside `onMessage`; the headers
arrive as `BlockHeadersReceivedMessage` on the same actor and are only stored
by `_handleBlockHeadersReceived`, which could not run while the handler held
the mailbox. Every opportunistic fetch timed out (10 s), blocking header sync
and the asking `SPVActor` for the whole timeout. Requests are now parked and
answered from `_handleBlockHeadersReceived`, with a timer for the timeout.
Regression tests in `test/actors/header_sync_actor_test.dart`.

**A-C2 · Critical · correctness · Fixed — Client-side channel open stalled
because `BuildFundingTransactionCommand` was sent to an actor that dropped
it.** `channel_p2p_adapter.dart:178`. The adapter told the channel manager a
wallet command that only `BitcoinWalletAggregate` handles; the manager's
`default:` discarded it and the refund/open sequence never started. The
adapter now routes it through the wallet manager with the coordinator as the
reply target.

**C1 · Critical · correctness · Fixed — Deferred-spend UTXOs could never be
marked spent and returned to `available` after the reservation expired.**
`bitcoin_wallet_aggregate.dart:879`. The payment coordinator reserves the
inputs and records the transaction with `deferSpend: true`, expecting ARC to
send `SpendUTXOCommand` at SEEN_ON_NETWORK, but `_handleSpendUTXO` rejected
any UTXO that was not `available`. Two minutes later the expiry cleanup
returned the on-chain-spent coin to `available` (balance overstated, coin
re-selectable). A spend now supersedes a reservation held by the same
transaction.

**S-01 · Critical · correctness · Open — Postgres channel read model cannot
work.** `postgres_wallet_storage.dart:1510, 1595`;
`channel_projection.dart:142-166`. The projection passes Isar
`PaymentChannelEntity` objects and Postgres casts them to `PaymentChannel`
(`TypeError` on every channel event); the conflict clause never updates the
server-side fields and three columns are missing.

**S-02 · Critical · correctness · Fixed — Postgres dropped `pluginMetadata`,
so token UTXOs were counted in the balance and selectable as payment
inputs.** Migration v003 adds `plugin_metadata JSONB`; `upsertUTXO` persists
it, `_rowToUtxo` hydrates it, and `getPaymentUTXOs` / `getBalance` /
`getUTXOsByPlugin` filter in SQL with the same `pluginId` rule as Isar.

**S-03 · Critical · correctness · Fixed — `block_headers.nonce INTEGER`
could not hold uint32 nonces.** Roughly half of all blocks (block 1's nonce
is 2573394689) failed to insert with "value out of range for type integer",
reported as an invalid header. v003 widens `nonce`, `version`, `bits` and
`timestamp` to `BIGINT`; bulk header import now runs in one transaction.

### High

**KM-1 · High · security · Mitigated — `InMemorySecureStorage` is the
silent default for every backend, including Postgres.**
`libspiffy_actor_system.dart:275`. Events are durable but key material lives
in a Dart `Map`: after a restart every wallet exists and none can sign. The
library ships no persistent `SecureStorage` other than the xpub-only Postgres
one. A SEVERE log is now emitted whenever a persistent backend falls back to
in-memory secrets. Open: make `secureStorage` required for persistent
backends and ship a persistent implementation.

**KM-2 · High · correctness · Fixed — The BIP39 passphrase was used to
derive the wallet's addresses at creation but never stored or used for
signing.** `bitcoin_wallet_aggregate.dart:575` vs `:1279, :1848`;
`payment_coordinator_actor.dart:798`. Addresses came from
seed(mnemonic, passphrase) and keys from seed(mnemonic, ''), so every
payment received by a passphrase wallet was unspendable from inside it. The
passphrase is now stored with the mnemonic and used at every derivation.

**KM-3 / H1 · High · correctness · Fixed — Two incompatible network-string
conventions.** The importer and actor system write `'main'` / `'test'`; the
aggregate, projection and coordinators compared against `'mainnet'` in some
places and `'main'` in others (`bitcoin_wallet_aggregate.dart:486, 695, 1048,
1231, 1819`; `wallet_projection.dart:184, 310`;
`payment_coordinator_actor.dart:793`; `benford_coordinator_actor.dart:307`).
Importing a mainnet WIF was rejected, a testnet key with `networkType:
'main'` passed, and on mainnet the outgoing-transaction output scanner
decoded change outputs with the testnet prefix so change never became a
UTXO. All comparisons go through `NetworkName`, the aggregate persists the
canonical spelling, and the projection reads the keys the backends actually
return (`'network'`, `'rootAddress'`; `'network_type'` and `'root_address'`
never existed). Open: an end-to-end mainnet WIF import test (bead KM-3).

**KM-6 / H2 · High · correctness · Fixed — Multi-input signing verified
input 0 against every UTXO.** `bitcoin_wallet_aggregate.dart:1387-1394`
hard-coded `inputIndex = 0` inside the per-input loop; with SIGHASH_FORKID
the check fails for any later input whose script or amount differs, and
`correctlySpends` throws, so multi-input `SignTransactionCommand`s failed.

**H3 · High · correctness · Open — Keys for change-chain addresses are never
derivable.** `generateChangeAddress` derives `m/1/{i}` but
`derivePrivateKey` always derives `m/0/{i}` and the aggregate records only
the index, so funds on change addresses are unspendable through the wallet.

**H4 · High · correctness · Open — Key material is stored after the success
response; a failed secure-storage write leaves an unrepairable keyless
wallet.** `bitcoin_wallet_aggregate.dart:119-200`.

**H5 · High · correctness · Fixed — WalletProjection double-counted an
address's balance and usage on its first UTXO and never debited it on
spend.** `wallet_projection.dart:329-358, 397-416`. Replay idempotency of
the delta-based address balance remains open under M2.

**A-H1 · High · correctness · Fixed — Timestamp BEEF was base64-encoded
where ARCActor hex-decodes it**, so timestamp archives were never broadcast
while `TimestampCompleteEvent(success: true)` was emitted.
`wallet_coordinator_actor.dart:890-901`.

**A-H2 · High · correctness · Fixed — dactor's default 5 s ask timeout
undercut every `AwaitEventApplied` window (10-30 s).** Seven ask sites now
pass an explicit ask timeout longer than the awaiter's window; under a slow
projection they used to report failure for operations that had succeeded and
leave reservations dangling.

**A-H3 · High · correctness · Open — SPVActor hardcodes testnet when
deriving output addresses** (`spv_actor.dart:538, 550`); on mainnet received
payments produce no spendable UTXOs.

**A-H4 · High · correctness · Fixed — "Timeout-as-success" UTXO
reservation.** The aggregate only replied on failure, so every payment,
provision and split waited 2 s and a slow rejection counted as success
(double-spend risk). `ReserveUTXOCommand` now gets a `UTXOReservedResponse`
on success and failure, and no reply is a failure.

**A-H5 · High · correctness · Fixed — `_syncInProgress` stuck true forever
when no peers were connected**, disabling header sync.
`header_sync_actor.dart:220-227`.

**A-H6 · High · correctness · Fixed — Failed address generation yielded an
invoice with an empty address** reported as success.
`invoice_coordinator_actor.dart:307-343`. The invoice now fails; wallet
manager error replies (`{'error': ...}` maps) are also handled instead of
leaking the pending request.

**A-H7 · High · correctness · Open — ImportActor cannot be cancelled and
sleeps its way through imports** (`import_actor.dart:60-107, 320, 337-354`).

**A-H8 · High · security · Open — Private keys are loaded and derived inside
PaymentCoordinator and BenfordCoordinator**, bypassing the aggregate's
signing path. Tracked with the pre-existing bead `libspiffy-leo`; KM-4
(plugin path signs every input with the first UTXO's key) and KM-5 (mnemonic
wallets cannot sign in the coordinators) are consequences.

**S-04 · High · correctness · Fixed — Isar `getChainTip` returned the
orphaned header after a reorg; `getBestHeight` ignored orphaning.**

**S-05 · High · correctness · Open — Transactions and UTXOs are keyed by
global txid**, so a second wallet in the same store never records a
transaction the first already holds.

**S-06 · High · correctness · Fixed — Postgres `storeWallet` reset
`network` to `'mainnet'` on every metadata update** (the `COALESCE` never
saw a null because the parameter was defaulted in Dart). The in-memory
backend now merges like the other two.

**S-07 · High · correctness · Open — Invoice storage methods return three
different types**; Postgres and in-memory throw at the coordinator's call
sites.

**S-08 · High · performance · Partially fixed — Postgres bulk header import
was one autocommit `INSERT` per header.** Now one transaction per batch;
a multi-row insert or `COPY` is still open.

**SPV-02 · High · security · Open — Header chain has no genesis/checkpoint
anchor, no difficulty validation and no fork choice**; the first peer to
answer defines the chain.

**SPV-03 · High · correctness · Open — Reorg handling is a no-op and reorg
batches are mis-heighted**, so the wallet stalls on a stale branch.

**SPV-04 · High · security · Open — CDN header sync trusts the CDN
entirely** (checkpoints from the manifest, no anchor on first sync, PoW off,
HTTP allowed).

**SPV-05 · High · security · Fixed — Path traversal: manifest-supplied
chunk filenames were joined into the wallet data directory.** Filenames
containing separators, `..` or NUL are rejected.

**SPV-06 · High · correctness · Open — Library-built BUMPs are not BRC-74
compliant** (two incompatible internal layouts); outgoing BEEFs are rejected
by standard verifiers.

## What was checked and found sound

- Cryptographic primitives: AES-256-GCM with CSPRNG nonces and verified tags,
  HKDF-bound row contexts, RFC 6979 low-S ECDSA via dartsv, `Random.secure()`
  everywhere, `SIGHASH_ALL|FORKID` at every signing site; the BRC-42
  (type-42) implementation matches the specification and its ten published
  test vectors; WIF/xpriv parsing rejects bad checksums, unknown prefixes and
  zero keys; `PostgresSecureStorage` refuses every private-key key name.
- No mnemonic, WIF, xpriv, private key or passphrase appears in any event,
  snapshot, command `toMap`, `toString`, log or exception.
- Every event type the aggregates emit is registered; `fromMap` accepts both
  `String` and `DateTime`; BigInt amounts are serialised as strings;
  `persistEvents` journals before state mutates; invoice and channel apply
  functions are pure.
- Under dactor 1.3 `context.sender` is stable across awaits in a handler;
  temporary receiver actors are stopped; timers are cancelled in `postStop`;
  projections are stopped before the event store is closed.
- All SQL is parameterised; BYTEA and TIMESTAMPTZ handling is correct;
  satoshi amounts fit `BIGINT`; credentials are not logged.
- BEEF/BUMP parsing of untrusted bytes terminates and bounds allocation; CDN
  chunk hashes are verified before parsing and cached chunks re-verified;
  WhatsOnChain retries are rate-limited; node-RPC credentials travel only in
  the Authorization header.

## Pre-existing test failures

Bead T-1 lists the 23 unit/integration tests and the two `payment_protocol_flow`
tests that fail identically on the pre-upgrade baseline. Most are stale
expectations (enum counts, default UTXO status, `ScriptTypeRegistry`
re-initialisation across tests of the dead `TransactionBuilderService`),
two are timing races in the tests themselves (they read the read model
before the projection has applied the event), and two depend on ARC's
SEEN_ON_NETWORK callback that the mock never sends (see C1). Isar's native
library also segfaults on process exit under `dart test` on both trees.
